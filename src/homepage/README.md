# homepage

[Homepage](https://gethomepage.dev) — a highly customizable application dashboard / start page.

- **Image:** `ghcr.io/gethomepage/homepage:v2.7.0`
- **Ingress:** port 3000
- **Config:** bind-mounted from `${HOLA_APP_DATA}/config` to `/app/config`. `services.yaml` is
  generated by the `homepage-registry` sidecar from Hola's `registry.json` (`consumes: app-registry`)
  and overwritten whenever the installed-app set changes — edit the other YAML files, not that one.
- **Runs as uid/gid 1000** (`PUID`/`PGID`), the same user as the sidecar. Homepage chowns
  `/app/config` to it at startup, so an install from before 1.4.1, whose config dir is root-owned,
  is fixed on its first start.
- **`HOMEPAGE_ALLOWED_HOSTS`** is required (since v1.0) — set it to `homepage.<your HOLA_BASE_DOMAIN>`.

## Auth

`forward-auth`: Homepage has no usable native authentication, so Hola gates it
behind Authentik's forward-auth proxy. Requires `HOLA_AUTH_MODE=authentik` on the
Hola host.

Homepage v2.0 added its own optional login gate (`HOMEPAGE_AUTH_ENABLED`, password or OIDC).
This bundle leaves it **off** — forward-auth already gates every request — and likewise leaves the
opt-in MCP endpoint (`HOMEPAGE_MCP_ENABLED`) off.

## Upgrading from 1.3.x (Homepage v1 → v2)

No action needed. v2.0's only breaking change is the opt-in auth gate above; the config file
formats (`services.yaml`, `settings.yaml`, …) are unchanged, so existing config and the generated
`services.yaml` carry over as-is. Release notes:
<https://github.com/gethomepage/homepage/releases/tag/v2.0.0>.

## Publish

```bash
./bin/push-oci-package.sh homepage ghcr.io/try-hola apps
```
